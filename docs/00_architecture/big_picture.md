# Обзор системы: Clothing CAD Automation

Система построена на взаимодействии Логического ядра (n8n), связующего Моста и Графического ядра (ExtendScript).

**Clothing CAD Automation** — это автономный агент для промышленного редактирования лекал и автоматизации графических процессов в Adobe Illustrator. Система позволяет превратить настольное графическое приложение в масштабируемый сервис, управляемый через современные API и мессенджеры.

---

## 1. Концепция

Традиционные САПР (CAD) для одежды часто требуют ручного вмешательства для рутинных операций: изменения размеров, замены фурнитуры или подготовки технической документации. Данный проект автоматизирует эти процессы, создавая "цифрового двойника" оператора Illustrator, который работает 24/7.

---

## 2. Поток данных (Data Flow)

Подробное описание механизмов обмена данными и синхронизации приведено в файле [data_flow.md](data_flow.md).

Система построена на базе трехуровневой архитектуры, обеспечивающей изоляцию сред и стабильность работы.

```text
[ User (Telegram) ] 
        ↓
[ n8n (Docker/Linux) ] 

        ↓ (HTTP + API Key)

[ FastAPI Bridge (Host/Windows) ] 

        ↓ (COM/OLE Automation)

[ Adobe Illustrator (ExtendScript) ]
```

---

## 3. Роли слоев

### Слой Интеграции: n8n (Логическое ядро)
*Оркестрация и интерфейс.*
- **Функции**: Работа с API Telegram, прием и фильтрация сообщений.
- **Управление**: Контроль очереди заданий, хранение состояния (Offset), распределение файлов по рабочим папкам задания.
- **Среда**: Контейнеризированная среда Docker (Linux).

### Слой Транспорта: Python Bridge (Мост)
*Связующее звено (Middleware).*
- **Функции**: Предоставление HTTP API для управления GUI-приложением на Windows.
- **Безопасность**: Валидация путей (Path Traversal Protection), проверка API-ключей.
- **Управление**: Мониторинг процесса Illustrator (Watchdog), очистка "зомби-процессов", трансляция путей между Docker и Windows.
- **Среда**: Windows Host (Native Python).

### Слой Исполнения: ExtendScript (Графическое ядро)
*Графическое ядро.*
- **Функции**: Прямое взаимодействие с объектной моделью (DOM) Illustrator.
- **Логика**: Выполнение геометрических преобразований, поиск объектов в сложных иерархиях (лекалах), экспорт финальных файлов (PDF/AI).
- **Среда**: Внутренняя среда Adobe Illustrator (ES3).

## 4. Бизнес-задачи и преимущества

### Работа в закрытых сетях (Polling)
Использование механизма **Manual Polling** позволяет системе функционировать без публичного IP-адреса и сложной настройки входящих соединений. Это критично для производственных площадок с жесткой политикой безопасности и DPI.

### Промышленная надежность
Архитектура спроектирована с учетом нестабильности десктопного ПО:
- Автоматический перезапуск зависших процессов.
- Изоляция каждого задания в отдельной файловой структуре.
- Полное логирование каждого шага для быстрого Troubleshooting.

### Масштабируемость
Благодаря четкому разделению на микросервисы, система поддерживает горизонтальное масштабирование. Для увеличения пропускной способности достаточно развернуть дополнительные инстансы Windows-хостов, сохранив единый центр управления в n8n.

---

## 5. Сетевая топология

Для взаимодействия между компонентами в разных средах (Docker и Windows Host) используется следующая конфигурация:
- **Порты**:
  - **n8n**: 5678 (доступен внутри Docker-сети и для пользователя).
  - **Bridge (FastAPI)**: 8000 (запущен на Windows Host).
- **Взаимодействие**: n8n обращается к Bridge по адресу `http://host.docker.internal:8000`. Это позволяет контейнеру Docker прозрачно взаимодействовать с сервисом, работающим непосредственно на операционной системе хоста.
