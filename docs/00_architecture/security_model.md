# Модель безопасности системы

В проекте Illustrator Automation реализована многоуровневая система защиты, которая предотвращает несанкционированный доступ к ресурсам сервера и гарантирует безопасность выполнения графических операций.

---

## 1. Четыре уровня защиты

Безопасность системы обеспечивается на каждом этапе прохождения данных — от внешнего запроса до исполнения внутри Adobe Illustrator.

### Уровень 1: Входной фильтр (Security Guard)
На уровне оркестратора n8n реализован механизм **Whitelist** (Белый список).
- **Проверка отправителя**: Система принимает сообщения только от доверенных Telegram Chat ID. Любые запросы от неизвестных пользователей игнорируются на самом раннем этапе.
- **Фильтрация данных**: Узел Security Guard проверяет структуру входящего сообщения, отсекая некорректные или подозрительные запросы до начала их обработки.

### Уровень 2: Транспортная безопасность (X-API-Key)
Взаимодействие между n8n (Docker) и Python Bridge (Windows Host) защищено механизмом авторизации.
- **Статический ключ**: Каждый HTTP-запрос к мосту должен содержать заголовок `X-API-Key`.
- **Изоляция ключей**: Ключ хранится в переменной окружения `BRIDGE_API_KEY` и не захардкожен в коде воркфлоу, что позволяет легко менять его без изменения логики системы.

### Уровень 3: Защита файловой системы (Path Traversal Protection)
Python Bridge имеет доступ к файловой системе хоста, поэтому защита путей является критически важной.
- **Валидация через Pathlib**: Все пути к файлам проходят через строгую проверку функцией `validate_secure_path`.
- **Резолвинг путей**: Система использует метод `.resolve()` для вычисления абсолютных путей и проверяет, что итоговый путь находится строго внутри разрешенной директории `exchange/jobs/`.
- **Блокировка переходов**: Любые попытки выйти за пределы рабочей папки (например, через `../`) блокируются и вызывают ошибку безопасности.

### Уровень 4: Безопасное исполнение (Strict Schema Validation)
Внутри среды ExtendScript реализована логика "безопасного исполнения" команд.
- **Безопасная обработка**: Вместо прямого исполнения кода из JSON, система использует его исключительно как структуру данных.
- **Строгая валидация**: Полученный объект проходит через [validator.js](/src/utils/validator.js), где каждое действие (resize, move и др.) проверяется на соответствие своей JSON-схеме.
- **Ограничение команд**: Система выполняет только те методы и свойства, которые явно разрешены в архитектуре проекта. Это исключает возможность выполнения произвольного кода через манипуляцию входными данными.
- **Fail-Fast**: При обнаружении любого несоответствия в параметрах, выполнение немедленно прерывается до того, как Illustrator начнет вносить изменения в документ.

## 2. Принцип "Песочницы" (Sandbox)

Архитектура системы построена по принципу минимальных привилегий.

- **Ограничение доступа**: Adobe Illustrator и Python Bridge работают в контексте папки `exchange/jobs/`. У них нет необходимости и прав на доступ к системным папкам Windows или другим пользовательским данным.
- **Изоляция задач**: Каждое задание (Job) имеет свою изолированную подпапку. Это гарантирует, что ошибки в одном чертеже или попытки манипуляции данными не затронут другие активные задачи.
- Временные ресурсы**: После завершения цикла (доставка результата + очистка), все данные задачи удаляются, не оставляя следов в системе.

---

## 3. Лимиты и квоты

Помимо программных проверок, система ограничивает потребление ресурсов:
1. **Размер файлов**: Ограничение в 200Мб защищает оперативную память сервера.
2. **Тайм-ауты**: Каждый вызов Illustrator ограничен 300 секундами, что предотвращает "вечные" процессы при сбоях в ExtendScript.
3. **Очередность**: Строгий лимит в 1 параллельную задачу (Concurrency: 1) гарантирует, что Illustrator не упадет от одновременных запросов.
