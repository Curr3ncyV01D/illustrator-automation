# Жизненный цикл задачи (Job Lifecycle)

Этот документ описывает состояния, через которые проходит задача автоматизации, и принципы обработки исключительных ситуаций в системе.

---

## 1. Состояния задачи (Job States)

Каждое задание в системе имеет строго определенный жизненный цикл, управляемый оркестратором n8n и диспетчером хоста.

```text
+------------+
|  PENDING   |  <-- Ожидание нового сообщения в Telegram
+------------+
      |
      v
+------------+
|INITIALIZING|  <-- Создание папок, скачивание файлов (n8n)
+------------+
      |
      v
+------------+
|   QUEUED   |  <-- Ожидание освобождения Illustrator (n8n -> Мост)
+------------+
      |
      v
+------------+
| PROCESSING |  <-- Выполнение скрипта в Illustrator (Мост -> Illustrator)
+------------+
      |       \ 
      |        \ 
      v         v
+----------+  +----------+
| FINISHED |  |  FAILED  |  <-- Успех или Ошибка
+----------+  +----------+
```

---

## 2. Матрица ответственности

| Действие | Исполнитель |
| :--- | :--- |
| Создание структуры папок | n8n |
| Скачивание файлов | n8n |
| Трансляция путей (Docker to Windows) | Мост |
| Генерация `runner.jsx` | Мост |
| Исполнение графической логики | Adobe Illustrator (JSX) |
| Финальная очистка | n8n |

---

## 3. Философия обработки ошибок

Система спроектирована для работы в автономном режиме, поэтому корректная обработка сбоев является приоритетом.

### Fail-Fast (Быстрый отказ)
Воркфлоу n8n придерживается стратегии немедленной остановки при обнаружении критической проблемы:
- Если отправитель не в Whitelist — выполнение прерывается.
- Если файлы не удалось скачать — выполнение прерывается.
- Если формат JSON не прошел валидацию — документ в Illustrator даже не открывается.
Это предотвращает накопление "битых" задач и некорректное изменение файлов.

### Early Exit (Ранний выход)
В процессе ожидания результата от Illustrator (цикл **Scanner Files** в n8n) используется механизм раннего обнаружения сбоев:
- Вместо того чтобы просто ждать таймаута (300 сек), система параллельно сканирует лог-файлы задачи.
- При обнаружении метки `[ERROR]` цикл ожидания немедленно прерывается.
- Пользователь получает отчет об ошибке сразу, не дожидаясь окончания общего таймаута.

### Cleanup Policy (Политика гигиены)
Независимо от результата выполнения задачи (**FINISHED** или **FAILED**), система обязана очистить временные ресурсы:
1. **Bridge**: Удаляет временный файл `runner.jsx` сразу после завершения скрипта.
2. **n8n**: Выполняет рекурсивное удаление папки `exchange/jobs/{job_id}/` после завершения всех операций.
Это гарантирует стабильную работу сервера 24/7 без переполнения дискового пространства.
