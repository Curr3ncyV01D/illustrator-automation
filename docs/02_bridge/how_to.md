# Руководство разработчика: Python Bridge

В этом разделе описаны инструкции по развертыванию, тестированию и расширению компонента **Python Bridge**.

---

## 1. Запуск для локальной разработки

Для работы моста на локальной машине (Windows) требуется установленный Adobe Illustrator.

### Шаг 1: Подготовка окружения
1. Создайте виртуальное окружение Python:
   ```bash
   python -m venv venv
   ```
2. Активируйте его:
   ```powershell
   .\venv\Scripts\activate
   ```
3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```

### Шаг 2: Настройка переменных окружения
Создайте файл `.env` в корне проекта (на основе `.env.example`):
```env
BRIDGE_API_KEY=your-secure-key
BRIDGE_JOB_TIMEOUT_SECONDS=300
```

### Шаг 3: Запуск сервера
Запустите FastAPI сервер с помощью `uvicorn`:
```bash
uvicorn bridge.main:app --host 0.0.0.0 --port 8000 --reload
```
Параметр `--reload` позволяет серверу автоматически перезагружаться при изменении кода.

## 2. Запуск интеграционных тестов

Интеграционные тесты проверяют всю цепочку: от HTTP-запроса до генерации PDF в Illustrator.

### Описание скрипта `test_integration.py`
Скрипт [test_integration.py](/dev/test_integration.py) выполняет следующие действия:
1. **Загрузка команд**: Берет JSON-файл из папки `dev/tests/`.
2. **Подготовка Workspace**: Эмулирует действия Node.js/n8n, создавая структуру папок в `exchange/jobs/{job_id}/`.
3. **Отправка запроса**: Вызывает `POST /process` с API-ключом.
4. **Ожидание результата**: Опрашивает папку вывода на наличие готового PDF.
5. **Анализ**: Если PDF не появился за отведенное время, выводит логи моста для диагностики.

### Как запустить тесты
Убедитесь, что Bridge запущен, затем выполните:
```bash
# Запуск теста по умолчанию (test_01_basic_ops.json)
python dev/test_integration.py

# Запуск конкретного сценария
python dev/test_integration.py --test dev/tests/test_02_replace.json
```

## 3. Как добавить новый API-эндпоинт

Если вам нужно расширить функциональность моста, следуйте этому алгоритму:

1. **Добавьте модель данных** в [models.py](/bridge/models.py):
   ```python
   class NewFeatureRequest(BaseModel):
       param1: str
       param2: int
   ```

2. **Определите бизнес-логику** в новом или существующем сервисе в папке `services/`. Например, в [workspace.py](/bridge/services/workspace.py) для работы с файлами.

3. **Создайте маршрут** в [main.py](/bridge/main.py):
   ```python
   @app.post("/new-feature")
   async def new_feature(request: NewFeatureRequest, _: str = Depends(verify_api_key)):
       # Вызов логики сервиса
       return {"status": "ok"}
   ```

4. **Обновите документацию** в `reference.md` и протестируйте новый эндпоинт.

## 4. Режим отладки (Debug Mode)

Для глубокого анализа работы моста и просмотра полного JSON-обмена в реальном времени можно повысить уровень детализации логов.

### Как включить отладку:
1. В файле [logger.py](/bridge/utils/logger.py) или при запуске через переменные окружения установите уровень логирования `DEBUG`.
2. Если вы используете `uvicorn`, запустите его с флагом `--log-level debug`:
   ```bash
   uvicorn bridge.main:app --host 0.0.0.0 --port 8000 --reload --log-level debug
   ```
3. В консоли начнут отображаться:
   - Полные тела входящих POST-запросов.
   - Детальные шаги подготовки Workspace.
   - Команды, передаваемые в Illustrator через COM.

## 5. Устранение COM-ошибок

При работе с Adobe Illustrator через PyWin32 могут возникать специфические ошибки Windows.

### Ошибка `Class not registered` или `Invalid class string`
Это означает, что Windows не может найти зарегистрированный COM-объект Illustrator.
- **Решение 1**: Запустите Adobe Illustrator один раз вручную от имени **Администратора**. Это заставит приложение обновить свои записи в реестре Windows.
- **Решение 2**: Перезапустите Python Bridge от имени Администратора.
- **Решение 3**: Проверьте, что версия Illustrator в реестре совпадает с установленной.

### Ошибка `Call was rejected by callee`
Illustrator занят обработкой другого запроса или открыл модальное окно.
- **Решение**: Убедитесь, что на экране нет диалоговых окон (сохранение, шрифты). Мост автоматически пытается убить "зомби-процессы", но иногда требуется ручное закрытие окон.
