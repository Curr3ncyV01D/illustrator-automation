# Технический справочник: n8n и Инфраструктура

Данный раздел описывает работу n8n, выполняющего роль Логического ядра системы.

Этот документ описывает инфраструктурную составляющую проекта, развернутую с помощью Docker, и логику работы управляющего воркфлоу в n8n.

---

## 1. Инфраструктурная карта (Docker)

Проект использует Docker для изоляции среды n8n и обеспечения консистентного доступа к файлам обмена.

### Схема структуры папок (Корень проекта)
```text
illustrator-automation/
├── bridge/             # Исходный код Python Bridge (запускается на Хосте)
├── exchange/           # Общая папка обмена (Shared Volume)
│   ├── jobs/           # Временные данные заданий
│   ├── library/        # Библиотека .ai компонентов
│   └── last_offset.txt # Хранилище смещения для очереди
├── n8n_data/           # База данных и настройки n8n (Persistence)
├── docker-compose.yml  # Конфигурация контейнеров
└── .env                # Переменные окружения
```

### Shared Volumes (Маппинг путей)
Для взаимодействия n8n (внутри Docker) и Python Bridge (на Windows-хосте) используется механизм общих томов.

| Локальный путь (Windows) | Путь в контейнере (n8n) | Назначение |
| :--- | :--- | :--- |
| `C:/illustrator-automation/exchange` | `/data/exchange` | Основной буфер для передачи .ai файлов и команд. |
| `C:/illustrator-automation/n8n_data` | `/home/node/.n8n` | Сохранение состояния n8n, воркфлоу и учетных записей. |

## 2. Переменные окружения (.env)

Эти переменные проброшены в контейнер n8n через `docker-compose.yml` и управляют поведением системы.

| Ключ | Значение / Пример | Описание |
| :--- | :--- | :--- |
| `BRIDGE_API_KEY` | `GOROX321` | Ключ авторизации для запросов к Python Bridge. |
| `BRIDGE_JOB_TIMEOUT_SECONDS` | `210` | Лимит времени ожидания ответа от моста. |
| `TZ` | `Europe/Moscow` | Часовой пояс для корректного логирования. |
| `N8N_RESTRICT_FILE_ACCESS_TO` | `/data/exchange/` | Ограничение доступа n8n к файловой системе контейнера (безопасность). |
| `NODE_FUNCTION_ALLOW_BUILTIN` | `fs,path` | Разрешение использования стандартных модулей Node.js в узлах "Code". Необходимы для базовых операций с путями и файлами. |
| `NODE_FUNCTION_ALLOW_EXTERNAL` | `fs-extra` | Разрешение внешних библиотек для работы с ФС. Используется для рекурсивного удаления папок и расширенного управления файлами. |
| `N8N_BLOCK_ENV_ACCESS_IN_NODE` | `false` | Позволяет узлам Code читать переменные окружения (нужно для API Key). |

## 3. Лимиты системы

Для обеспечения стабильности работы установлены следующие ограничения:

| Параметр | Значение | Описание |
| :--- | :--- | :--- |
| **Макс. размер файла** | 200 MB | Ограничение на входящий .ai файл для предотвращения переполнения памяти. |
| **Тайм-аут моста** | 300 сек | Максимальное время ожидания ответа от Python Bridge до принудительной остановки. |
| **Интервал опроса Telegram** | 15 сек | Частота запросов `getUpdates` для проверки новых сообщений. |
| **Лимит очереди** | 10 сообщений | Максимальное количество задач, забираемых за один цикл опроса. |

## 4. Коды ответов и диагностика

В таблице ниже описаны основные ошибки, которые могут возникнуть в процессе работы, и их значение.

| Код / Ошибка | Значение | Рекомендуемое действие |
| :--- | :--- | :--- |
| **429 (Busy)** | Мост занят обработкой другого задания. | Подождать 30-60 секунд и повторить попытку. |
| **401 (Unauthorized)** | Ошибка авторизации. Неверный `BRIDGE_API_KEY`. | Проверить соответствие ключей в `.env` файле и перезапустить Docker. |
| **Error [OPERATION]** | Сбой логики внутри Adobe Illustrator (ExtendScript). | Проверить лог-файл в `output/logs/` для поиска конкретной ошибки в JSX. |
| **Timeout** | Зависание процесса Illustrator или слишком сложная задача. | Проверить, не открыто ли в Illustrator модальное окно, требующее участия пользователя. |

## 5. Подробный разбор узлов Воркфлоу

Воркфлоу разделен на логические фазы: от контроля очереди до «умного» мониторинга исполнения.

### Фаза А: Вход и управление состоянием
*   **Load Offset**: Читает значение из `last_offset.txt`. Это точка входа, гарантирующая, что система не будет обрабатывать старые сообщения повторно.
*   **getUpdates**: HTTP-запрос к Telegram API. Использует динамический `offset`, чтобы забирать только новые события.
*   **Save Offset**: Вызывается сразу после того, как задача сформирована. Записывает `latest_update_id + 1`. Это критически важно: даже если дальше произойдет сбой, бот уже «забыл» это сообщение и не зациклится.

### Фаза Б: Фильтрация и бизнес-логика
*   **Security Guard**: Жесткий фильтр по `chat_id`. Если отправитель не в «белом списке», выполнение мгновенно прерывается без уведомления.
*   **AI Finder**: Анализирует массив обновлений. Ищет последний присланный файл `.ai`. Если его нет, цепочка останавливается.
*   **JSON Matcher**: Ищет «пару» (инструкции) к найденному AI-файлу. Логика связи: совпадение `media_group_id` (отправлены группой) или разница во времени менее 60 секунд.
*   **Job Architect**: «Мозг» подготовки. 
    *   Генерирует уникальный `job_id`.
    *   Вычисляет пути для Docker (`/data/exchange/...`) и Windows.
    *   **Валидация:** Проверяет `file_size`. Если файл > 200Мб, уходит на ветку ошибки `Notify: File Too Large`.

### Фаза В: Подготовка инфраструктуры
*   **MakeDir**: Выполняет системную команду `mkdir`. Создает дерево папок для конкретной задачи (`input/source_files`, `output/pdf`, `output/ai`, `output/logs`).
*   **Download AI/JSON**: Последовательно скачивает файлы через Telegram API и сохраняет их на диск в папку задачи.

### Фаза Г: Контроль конкурентности (Handshake)
*   **Check Bridge Status**: Опрашивает эндпоинт `/status` моста. 
*   **If Busy? (Петля ожидания)**: Если Illustrator занят другой задачей (`is_busy: true`), воркфлоу уходит в петлю через узел **Wait 10s**. Это защищает Illustrator от крашей при попытке открыть два файла одновременно.

### Фаза Д: Исполнение и Watchdog (Мониторинг)
*   **Prepare Payload**: Читает скачанный JSON-файл с командами и упаковывает его содержимое в тело POST-запроса. Это избавляет мост от необходимости самому парсить файлы.
*   **Call Python Bridge**: Инициирует обработку. Имеет таймаут 300 сек.
*   **Monitor Logs**: Каждые 2 секунды сканирует файл лога в папке задачи. Если находит тег `[ERROR]`, инициирует **Ранний выход (Early Exit)**, не дожидаясь таймаута.
*   **Scanner Files**: Проверяет наличие результата (одновременно PDF и AI) в папках вывода.
*   **Check Timeout**: Счетчик попыток. Если за 210 секунд файлы не появились и ошибок нет — прерывает операцию по таймауту.

### Фаза Е: Доставка и очистка
*   **Read & Send (Multi-file)**: Последовательно читает PDF и AI с диска и отправляет их в Telegram. 
*   **Cleanup Nodes**: Узлы `rm -rf`, которые срабатывают при критических ошибках (429, ошибка авторизации, отсутствие JSON), чтобы не оставлять мусорные папки на диске.

## 4. Ресурсы обмена: Структура задания

Каждое задание (Job) создает свою изолированную структуру папок внутри `exchange/jobs/{job_id}/`.

| Папка | Содержимое | Описание |
| :--- | :--- | :--- |
| `input/` | `commands.json` | Файл с инструкциями для ExtendScript. |
| `input/source_files/` | `*.ai` | Копия исходного шаблона, который будет редактироваться. |
| `output/ai/` | `*.ai` | Результат работы Illustrator (сохраненный файл). |
| `output/pdf/` | `*.pdf` | Экспортированный PDF файл (финальный артефакт). |
| `output/logs/` | `*.log` | Логи выполнения скрипта внутри Illustrator для диагностики. |
