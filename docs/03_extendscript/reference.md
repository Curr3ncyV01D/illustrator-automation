# Справочник ExtendScript (src/)

Данный раздел описывает ExtendScript-ядро, выполняющее роль Графического ядра системы.

Данный раздел содержит техническое описание архитектуры и компонентов ExtendScript, используемых для автоматизации Adobe Illustrator.

## Структура папки `src/`

```text
src/
├── config/           # Конфигурационные файлы (пути, настройки)
├── core/             # Ядро (оркестратор и процессор команд)
├── operations/       # Логика конкретных действий (resize, move и т.д.)
├── schemas/          # JSON-схемы для валидации команд
└── utils/            # Вспомогательные модули (логи, валидаторы)
```
---
## Архитектура проекта

Внутренняя структура проекта организована по модульному принципу для обеспечения масштабируемости и простоты тестирования в среде ES3.

| Папка | Описание | Основные файлы |
| :--- | :--- | :--- |
| `config/` | Глобальные настройки, константы и пути. | [config.js](/src/config/config.js), [constants.js](/src/config/constants.js) |
| `core/` | Ядро системы: управление потоком выполнения и обработка команд. | [orchestrator.js](/src/core/orchestrator.js), [commandProcessor.js](/src/core/commandProcessor.js) |
| `operations/` | Реализация конкретных действий над объектами Illustrator. | [baseOperation.js](/src/operations/baseOperation.js), [operationRegistry.js](/src/operations/operationRegistry.js) |
| `schemas/` | JSON-схемы для валидации входных данных и параметров операций. | [main.schema.json](/src/schemas/main.schema.json), [operationSchema.json](/src/schemas/operationSchema.json) |
| `utils/` | Вспомогательные модули: логгер, обработчик ошибок, валидатор. | [errorHandler.js](/src/utils/errorHandler.js), [logger.js](/src/utils/logger.js), [validator.js](/src/utils/validator.js) |
| `utils/modules/` | Специализированные утилиты для работы с объектами и геометрией. | [objectFinder.js](/src/utils/modules/objectFinder.js), [unitConverter.js](/src/utils/modules/unitConverter.js) |

## 1. Инициализация и Контекст (Context Injection)

Ядро ExtendScript не выполняет самообнаружение путей. Вместо этого оно полагается на **инъекцию контекста** от Моста через метод `Config.init()`.

### Метод `Config.init(codeRoot, dataRoot, jobId)`
Вызывается в самом начале выполнения Раннера.

- **`codeRoot`**: Абсолютный путь к директории `src/`. Используется для подключения модулей, утилит и схем.
- **`dataRoot`**: Абсолютный путь к директории `exchange/`. Используется как база для поиска файлов задач.
- **`jobId`**: Уникальный идентификатор задачи. На его основе строятся пути: `dataRoot + "/jobs/" + jobId + "/input/"`.

### Точка входа: `main()`
Файл [main.js](/src/core/main.js) содержит универсальную функцию `main(jsonFilePath, jobId, codeRoot, dataRoot)`, которая:
1. Принимает все параметры от Раннера.
2. Инициализирует глобальные объекты `Config` и `Logger`.
3. Запускает цикл обработки команд через `Orchestrator`.



## 2. Оркестрация

Управление потоком выполнения команд разделено на два уровня:

### Orchestrator ([orchestrator.js](/src/core/orchestrator.js))
Отвечает за высокоуровневое планирование. Основная задача — анализ зависимостей между операциями.
- Использует **алгоритм Кана** для топологической сортировки операций.
- Гарантирует, что операции выполняются в правильном порядке (например, объект создается до того, как к нему применится изменение цвета).
- Прерывает выполнение всей цепочки при критической ошибке в одной из операций.

### CommandProcessor ([commandProcessor.js](/src/core/commandProcessor.js))
Отвечает за выполнение конкретной команды.
- **Валидация**: Проверяет структуру команды через `Validator`.
- **Поиск объекта**: Использует `Helpers.finder` для нахождения целевого объекта в документе Illustrator по его имени.
- **Инстанцирование**: Запрашивает нужный класс операции у `OperationRegistry`.
- **Выполнение**: Вызывает метод `execute()` у созданной операции и возвращает результат.

## 3. Реестр операций (Operation Registry)

Все доступные операции регистрируются в [operationRegistry.js](/src/operations/operationRegistry.js). Реестр управляет соответствием между типом команды в JSON и классом реализации операции.

| Тип операции | Класс реализации | Схема валидации (в `schemas/`) | Описание |
| :--- | :--- | :--- | :--- |
| `resize` | `ResizeOperation` | [resize.schema.json](/src/schemas/resize.schema.json) | Изменение размеров объекта (ширина, высота). |
| `move` | `MoveOperation` | [move.schema.json](/src/schemas/move.schema.json) | Перемещение объекта (абсолютное или относительное). |
| `replaceObject` | `ReplaceOperation` | [replaceObject.schema.json](/src/schemas/replaceObject.schema.json) | Замена объекта другим файлом/символом. |
| `createConfectionCard` | `ConfectionCardOperation` | [createConfectionCard.schema.json](/src/schemas/createConfectionCard.schema.json) | Создание карты изделия на основе шаблона. |

Регистрация происходит в методе `initialize()`:
```javascript
this.register(Config.OPERATION_TYPES.RESIZE, ResizeOperation);
this.register(Config.OPERATION_TYPES.MOVE, MoveOperation);
// ... и другие
```

## 4. Обработка ошибок (ErrorHandler)

Механизм обработки ошибок реализован в [errorHandler.js](/src/utils/errorHandler.js) и обеспечивает централизованный контроль за сбоями.

### Класс AppError
Базовый класс для всех ошибок в системе. Содержит:
- `code`: Уникальный строковый код ошибки из `ERROR_CODES`.
- `message`: Человекочитаемое описание (автоматически подставляется из `ErrorMessages` по коду).
- `context`: Строка, указывающая на место возникновения ошибки (например, имя функции).

### Основные функции
- **`createError(code, customMessage, context)`**: Фабричный метод для создания объектов `AppError`. Если `customMessage` не передан, используется стандартное сообщение для данного кода.
- **`gracefulExit(error, logger)`**: Выполняет логирование ошибки и принудительно останавливает выполнение скрипта (через `throw error`), чтобы предотвратить некорректное состояние документа.
- **`getErrorMessage(code)`**: Возвращает локализованное описание ошибки по её коду.

### Коды ошибок (`ERROR_CODES`)
| Код | Описание (из `ErrorMessages`) |
| :--- | :--- |
| `OBJECT_NOT_FOUND` | Объект не найден в документе. |
| `INVALID_OPERATION` | Недопустимая операция (не зарегистрирована в реестре). |
| `INVALID_PARAMETERS` | Параметры операции не прошли валидацию. |
| `VALIDATION_ERROR` | Общая ошибка структуры входного JSON. |
| `DOCUMENT_NOT_OPEN` | Отсутствует активный документ в Illustrator. |
| `FILE_NOT_FOUND` | Указанный файл (например, для замены) не найден. |
| `EXECUTION_ERROR` | Общая ошибка во время выполнения логики операции. |

## 5. Система логирования

Логирование в ExtendScript реализовано через модуль [logger.js](/src/utils/logger.js) и служит основным инструментом диагностики как для разработчиков, так и для автоматизированных систем.

### Уровни логирования (`LOG_LEVELS`)
| Уровень | Описание | Применение |
| :--- | :--- | :--- |
| `INFO` | Информационные сообщения. | Начало этапа, успех операции, параметры задачи. |
| `WARN` | Предупреждения. | Необязательные объекты не найдены, отклонения от нормы. |
| `ERROR` | Ошибки. | Сбой операции, отсутствие файлов, ошибки валидации. |
| `DEBUG` | Отладочная информация. | Детальные дампы объектов, промежуточные вычисления. |

### Формат лога
Каждая запись имеет строгий формат:
`[YYYY-MM-DDTHH:mm:ss.SSSZ] [LEVEL] [STAGE] message`

**Важно для интеграции:** Мост Python (компонент Bridge) сканирует файлы логов и ищет именно подстроку `[ERROR]`. Её наличие является сигналом о том, что выполнение задания в Illustrator завершилось аварийно, даже если сам процесс не "упал".

## 6. Политика прерываний

Система оркестрации в [orchestrator.js](/src/core/orchestrator.js) придерживается политики "Fail-Fast" для предотвращения некорректного изменения чертежей.

| Событие | Действие системы | Последствия |
| :--- | :--- | :--- |
| **Ошибка валидации** | Остановка до открытия файла. | Документ не изменяется, возвращается код `VALIDATION_ERROR`. |
| **Сбой операции (execute)** | Прерывание всей цепочки (Chain Stop). | Остальные операции в списке игнорируются. |
| **Критическая ошибка** | Запись `[ERROR]` в лог. | Мост фиксирует сбой через Log Analyzer. |
| **Завершение (любое)** | Закрытие документа без сохранения. | Оригинальный файл-шаблон остается нетронутым. |

## 7. Геометрия и Единицы измерения

Adobe Illustrator внутренне работает в пунктах (**points**, pt), где `1 pt = 1/72 дюйма`. Для удобства пользователя внешние интерфейсы (JSON) всегда оперируют миллиметрами (**mm**).

### Конвертация ([unitConverter.js](/src/utils/modules/unitConverter.js))
- **Входящие данные**: Все числовые значения в JSON (координаты, размеры) интерпретируются как миллиметры.
- **Процесс**: Перед применением к объекту значение проходит через `UnitConverter.toPoints()`.
- **Точность**: Используется коэффициент `2.83465` (1 мм = 2.83465 pt). При обратной конвертации или расчетах система сохраняет до 5 знаков после запятой, что обеспечивает микронную точность в чертежах.

### Точка трансформации
По умолчанию все операции изменения размера (`resize`) и перемещения (`move`) выполняются относительно **центра** объекта (`Transformation.CENTER`), если иное не указано в параметрах команды.

## 6. Алгоритм поиска (Target Matching)

Поиск целевых объектов в документе реализован в модуле [objectFinder.js](/src/utils/modules/objectFinder.js).

### Стратегии поиска
1. **Прямое совпадение**: Сначала проверяются все объекты первого уровня в активном документе. Имя должно **строго совпадать** с полем `target` в JSON (**с учетом регистра**).
2. **Иерархический поиск**: Поддерживается синтаксис `"Слой/Объект"` или `"Группа/Объект"`. Система сначала находит контейнер, а затем ищет цель внутри него.
3. **Рекурсивный обход групп**: Если объект не найден на верхнем уровне, `ObjectFinder` начинает глубокий обход всех `GroupItem`. Это позволяет находить элементы, вложенные в сложные лекала или логические группы.

### Особенности
- **Регистрозависимость**: Поиск чувствителен к регистру (`"Part1"` и `"part1"` — разные объекты).
- **Дубликаты**: Если в документе несколько объектов с одинаковым именем, будет выбран **первый найденный** в дереве объектов Illustrator. `Рекомендуется использовать уникальные имена для целевых элементов!`
